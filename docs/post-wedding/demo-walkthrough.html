◔ First · Set the stage

Load the demo & sign in

Wipe any old broken preview data, seed a fresh realistic set, and start the server. Your admin password survives the wipe (it lives in .env).

# stop the server if it's running, then from the repo root: $ rm -f data/wedding.db data/wedding.db-wal data/wedding.db-shm $ rm -rf data/uploads $ npm run seed:demo # downloads real photos/videos (~1 min first run) $ npm start
Open http://localhost:3000
Admin login /admin → the admin password you set It's whatever you configured via npm run setup (stored hashed in .env). Forgot it? Re-run npm run setup to set a new one, then restart the server.
Guest · trusted Invite code LOVEBIRD → posts go live instantly On /gallery or /guestbook, the first time you post you'll be asked who's celebrating. Enter the code + any name.
Guest · untrusted "I don't have a code" → name only → posts are held for review This is how most guests will actually sign up. Use it to feel the moderation path from their side.
For the full experience, set two optional values in .env before you start: CONTACT_EMAIL (makes the gallery's "Report this photo" link appear) and an email service (RESEND_API_KEY + FROM_EMAIL, so guest "Recover by email" links actually send). Everything else works without them.
